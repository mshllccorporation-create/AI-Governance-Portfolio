# SOC 2 Mapping for SOC Operations

This is an illustrative portfolio mapping, not a SOC 2 audit opinion or certification.

| SOC 2 area | SOC operations activity | Evidence pattern |
|---|---|---|
| CC6 Logical access | Investigate accounts, privilege changes, token replay, and identity compromise | Identity evidence, response action, and verification |
| CC7 System operations | Validate SIEM, EDR, identity, email, network, cloud, and endpoint telemetry | Monitoring source, coverage status, alert, timeline, and gap owner |
| CC7 Incident response | Triage, scope, contain, escalate, recover, close, and record residual risk | Incident record, severity, confidence, owner, action audit, and closure evidence |
| CC8 Change management | Review production changes, maintenance, exceptions, and control changes | Change record, approval, affected service, exception expiry, and verification |
| CC9 Risk mitigation | Track unresolved exposure, vendor dependencies, and corrective actions | Risk, treatment decision, owner, due date, acceptance, and verification |

The SOC playbook supports operational evidence, but a complete SOC 2 program also requires policies, access reviews, change approvals, vulnerability management, vendor oversight, backup testing, training, control testing, and management review.
